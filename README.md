# Stashapi
An API wrapper for [Stash](https://github.com/stashapp/stash) written in R

## Installation
Stashapi can be installed directly from this repository:

```
remotes::install_github()
```

## Setup
To use the package we first need to establish a connection with an instance of [Stash](https://github.com/stashapp/stash). Specifically the url to the GraphQL endpoint of Stash and the API key need to be specified.

Setting connection credentials is currently done via a credentials file with two lines. The first line being the URL to the endpoint and the second line being the API key. The API key can be obtained under Settings > Security

Now specify the path to the credentials file to the `setStashCredentials()` function.

```R
library(stashapi)
setStashCredentials(".stash_credentials")
```

Connection details are stored within a session in the package environment. After restarting the R session `setStashCredentials()` has to be executed again.

## Usage
> **_NOTE:_** All functions within [R/stashapi_functions.R](R/stashapi_functions.R) are auto generated by processing an [introspection query](https://graphql.org/learn/introspection/). Function and argument descriptions are copied from the GraphQL schema if present. The lack of explicit function examples is due to the automated nature of creating the functions.

> **_DISCLAIMER:_** Using mutating functions like the *create, *update or *destroy functions will alter the database of stash. Proceed with caution.

### The Playground:
Stash instances come bundled with a GraphQL playground that is schema aware and hosts the full schema documentation. You can access the playground by visiting `/playground` on your instance: e.g. `http://localhost:9999/playground`. The playground is a good place to experiment with queries.

### Query Examples
The principle is always the same. Here are some examples for the most common queries:

#### Tags
```R
# Will return the first 25 tags
findTags()

# To query for more than 25 or even all tags use the filter argument
findTags(filter = list(per_page = -1)) # All tags
findTags(filter = list(per_page = 250))

# The .field argument will return only the specified field/column if present in the response
findTags(.field = "count")

# Find Tags with the name "4k"
findTags(tagfilter = list(name = list(value = "4k", modifier = "EQUALS")))

# Only return the id column instead of the entire tag entry
findTags(tagfilter = list(name = list(value = "4k", modifier = "EQUALS")), .field = c("tags", "id"))
```

#### Scenes
```R
# Filters can be combined
findScenes(
  scenefilter = list(tags = list(value = 182, modifier = "INCLUDES"), 
                     performers = list(value = 84, modifier = "INCLUDES_ALL"))
)

```

#### Images
```R
# Find images of a specified studio. page = 4 returns the 4th page of images with 250 images per page.
findImages(imagefilter = list(studios = list(value = 25, modifier = "INCLUDES")), filter = list(per_page = 250, page = 4))

# Returning all images of a performer can take a long time depending on the number of images a performer has
# It makes sense to check with .field = "count" first
findImages(imagefilter = list(performers = list(value = 84, modifier = "INCLUDES")), .field = "count")
findImages(imagefilter = list(performers = list(value = 84, modifier = "INCLUDES")), filter = list(per_page = -1))
```

#### Performers
```R
# Instead of the name filter we can also use the search. 
# Just be aware that they will yield different results
findPerformers(filter = list(q = "Leah", per_page = -1))
findPerformers(performerfilter = list(name = list(value = "Leah", modifier = "INCLUDES")), filter = list(per_page = -1))

# Like in the example above the .field argument will select the specified columns from the response
findPerformers(filter = list(q = "Leah", per_page = -1), .field = c("performers", "eye_color"))
# or
findPerformers(filter = list(q = "Leah"), .field = "count")
```

### Mutation Examples
Creating, updating or destroying Objects also follows the same principle. Inputs to these functions have to be specified properly. Proper formatting can be derived from the schema documentation in [the Playground](#the-playground)

#### Creation

```R
# Create a Tag
tagCreate(input = list(name = "TestTag", description = "Description of Tag", aliases = c("testtag", "TESTTAG")))
# Create a Studio
studioCreate(input = list(name = "TestStudio", url = "https://example.com", image = "https://url.to/image"))
```

#### Updating
```R
# Input fields not mentioned stay unchanged
imageUpdate(input = list(id = 52, organized = TRUE, date = "2025-01-01"))

# Updating a single scene this way will overrite the performers field. Other existing performers (except 84) will be unset.
sceneUpdate(input = list(id = 3826, performer_ids = c(84)))

# This will preserve existing performers since the mode is set to "ADD" 
bulkSceneUpdate(input = list(ids = 3826, performer_ids = list(mode = "ADD", ids = c(84))))
```

#### Destroy
The destroy family of functions only needs the id as input
```R
tagDestroy(input = list(id = ID))
studioDestroy(input = list(id = ID))
# Destruction of multiple items is also possible:
tagsDestroy(ids = c(ID1, ID2, ID3))
```
